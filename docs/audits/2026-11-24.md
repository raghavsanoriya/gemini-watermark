# GemClean audit, 2026-11-24

First run of the `/audit` skill (`.claude/skills/audit`), using the vendored
`auditing-code-for-vulnerabilities`, `owasp-security`, `sharp-edges`, `auditing-supply-chain`,
`vercel-react-best-practices` and `web-design-guidelines` skills. Scope: the whole tree at
`a0a3cbf` on branch `main-k7sa8a`.

**Summary:** no critical or high-severity issue. Two medium issues in the optional server
upload API could exhaust server memory from small requests; both are fixed, along with six
low-severity issues. All fixes are in `45a119c`, each with a test that fails on the old code.

## Findings

### [MEDIUM] Decode bomb: a 130 KB upload used 1.3 GB of server memory (CWE-400, OWASP A06:2025) - Fixed in 45a119c
Location:   `src/server/clean.ts` (decode), `src/lib/processors/pipeline.ts` (copies)
Path:       `POST /api/clean` (no login) -> `cleanUploadedImage` -> sharp decode with a 40 MP cap -> pipeline copies
Impact:     a flat 6400x6250 PNG compresses to 129 KB but decoded to 160 MB of RGBA, and the
            pipeline then made several full-size copies: 1.29 GB peak and 5 s of CPU per request.
            A few in parallel could exhaust a 2 GB function and run up hosting costs; the
            per-address rate limit (20 per 10 minutes) slows but does not stop this.
Fix:        read the header first and refuse more than 24 MP (Gemini's largest outputs are about
            17 MP); drop the full-size copy the pipeline made even when a mark was found. Now
            refused in 5 ms at 147 MB; a 4096x4096 image peaks at about 710 MB.
Confidence: Confirmed (measured on a local production build).

### [MEDIUM on self-hosted `next start`, LOW on Vercel] Whole body buffered before the size check (CWE-770, OWASP A06:2025) - Fixed in 45a119c
Location:   `src/app/api/clean/route.server.ts` (`request.formData()` before `cleanUploadedImage`'s size check)
Path:       `POST /api/clean` -> `formData()` buffers everything -> 413 only afterwards
Impact:     a 60 MB post added ~180 MB of server memory before being rejected; concurrent posts
            multiply it. Vercel rejects bodies over 4.5 MB at the edge, so production on Vercel
            was not exposed; `next start`, which the README lists as a server-mode build, was.
Fix:        `src/server/upload.ts` refuses an oversized declared length without reading and
            cuts a streamed body off at the limit. Now 413 in 0.05 s with +23 MB.
Confidence: Confirmed.

### [LOW] Decoders beyond PNG/JPEG/WebP reachable through the upload's label (CWE-434, OWASP A01:2025) - Fixed in 45a119c
Location:   `src/server/clean.ts`
Path:       multipart part labelled `image/png` -> sharp decodes whatever the bytes are (SVG via librsvg, GIF, TIFF)
Impact:     widens the attack surface to decoders the feature never needed; no exploit shown.
Fix:        accept only `png`, `jpeg` and `webp` as detected from the bytes (415 otherwise).
Confidence: Confirmed (an SVG labelled PNG was processed).

### [LOW] Setting typos silently disabled the upload and rate limits (CWE-1188, sharp-edges "configuration cliff") - Fixed in 45a119c
Location:   `src/server/config.ts`
Path:       `GEMCLEAN_MAX_UPLOAD_MB=4MB` -> `Number()` -> NaN -> `size > NaN` is false -> no limit; `GEMCLEAN_RATE_LIMIT=abc` -> no rate limit; `GEMCLEAN_RATE_WINDOW_MINUTES=abc` -> window never resets
Impact:     operator error only, but it fails open.
Fix:        `positiveNumber()` keeps the default for missing, empty, zero, negative or
            non-numeric values and logs a warning.
Confidence: Confirmed.

### [LOW] Rate limiter trusts `X-Forwarded-For` and its memory was unbounded (CWE-348, CWE-770) - Partly fixed in 45a119c
Location:   `src/server/rate-limit.ts`
Path:       client-chosen `X-Forwarded-For` -> per-address window key
Impact:     on Vercel the platform sets this header and drops client values, so no exposure.
            Behind no proxy (`next start` alone) a client can pick a new key per request, skip
            the limit, and grow the map without bound within a window.
Fix:        the map is now capped at 10,000 addresses (oldest dropped). The trust requirement
            is documented in code: self-hosting needs a proxy that sets the header. Still open
            by design for a bare `next start`.
Confidence: Confirmed by code; Vercel behaviour per platform documentation.

### [LOW] CI build job held deploy permissions (CWE-250, OWASP A03:2025) - Fixed in 45a119c
Location:   `.github/workflows/deploy-pages.yml`
Path:       workflow-level `pages: write` and `id-token: write` -> build job -> `npm ci` runs dependency install scripts
Impact:     a compromised dependency's install script could have requested a deploy token.
Fix:        read-only at workflow level; `pages: write` and `id-token: write` on the deploy job
            only. Takes effect on the next push to `main`; check that the Pages deploy succeeds.
Confidence: Confirmed by configuration review.

### [LOW] Diagnostic header carried server error text (CWE-209) - Fixed in 45a119c
Location:   `src/app/api/clean/route.server.ts` (`X-GemClean-Migan-Error`)
Impact:     a failing model load returned its error message, which can name server paths.
Fix:        the header is now the flag `unavailable`; the text stays in the server log.
Confidence: Confirmed by code.

### [LOW, performance] Flow import kept every decompressed image in memory - Fixed in 45a119c
Location:   `src/components/FlowProjectWorkspace.tsx`, `src/lib/flow/archive.ts`
Impact:     the background metadata scan (added 2026-11-23) loaded each ZIP entry through the
            cached `loadFile`, so a large Flow export stayed fully decompressed in the tab.
Fix:        a `readUncached` read for passes over every asset.
Confidence: Confirmed by code; regression introduced in this branch, not in production.

## Reviewed and clear

- **Metadata scanner and stripper:** every loop advances by at least its chunk header, every
  length is bounds-checked, the EXIF reader follows one level only (no offset cycles), and the
  regexes are linear. A malformed file cannot hang or overflow it.
- **ZIP and folder import:** entry names with `..`, absolute paths or drive letters are rejected;
  CRC and overlapping-entry checks are on; 512 MB per-entry cap. Worst case is the user's own
  tab with a file they chose.
- **Google Drive import:** `drive.file` scope, token held in memory only, file IDs URL-encoded.
- **Security headers:** CSP, `nosniff`, `Referrer-Policy`, `Permissions-Policy`,
  `X-Frame-Options: DENY`, COOP present on the live site; Vercel adds HSTS with preload.
  `unsafe-inline` and `unsafe-eval` are documented and needed (static bootstrap, HEIC decoder).
  `connect-src 'self'` holds: both AI models are self-hosted.
- **Model integrity:** both models are pinned by SHA-256 and verified at every build; LaMa's URL
  is also pinned to a commit.
- **Dependencies:** `npm audit --omit=dev` reports 0 vulnerabilities; install scripts only in
  esbuild, fsevents, unrs-resolver (dev) and protobufjs; CI installs with `npm ci`. Actions are
  GitHub-owned and referenced by major tag, which the supply-chain skill accepts.
- **React/Next.js:** heavy libraries (ONNX Runtime, zip.js, HEIC decoder, batch view) load on
  demand; the one `localStorage` value is validated and wrapped in try/catch; module-level server
  state is limited to the rate-limit map and model sessions (no per-user data).
- **UI:** global `:focus-visible` outline, reduced-motion support, labelled controls (the
  before/after slider is labelled through a visually hidden span), image dimensions set.
